# Frontend Data Safety & Sanitization Guidelines

> XSS prevention, DOMPurify sanitization, and input integrity in `agent-ui`.

---

## 1. Zero Untrusted HTML Injection

All dynamic content generated by AI or submitted by users must be strictly sanitized before rendering into the DOM:

### Safe Rendering Pipeline
```javascript
function renderMarkdownSafely(markdownText) {
  if (!markdownText) return '';
  
  // 1. Convert Markdown to HTML using marked.js
  const rawHtml = marked.parse(markdownText, {
    gfm: true,
    breaks: true
  });
  
  // 2. Sanitize HTML using DOMPurify with strict allowed tags
  const cleanHtml = DOMPurify.sanitize(rawHtml, {
    ALLOWED_TAGS: [
      'p', 'br', 'b', 'i', 'em', 'strong', 'a', 'ul', 'ol', 'li',
      'code', 'pre', 'blockquote', 'table', 'thead', 'tbody', 'tr',
      'th', 'td', 'h1', 'h2', 'h3', 'h4', 'h5', 'h6', 'span', 'div'
    ],
    ALLOWED_ATTR: ['href', 'target', 'class', 'id', 'data-page', 'data-node']
  });
  
  return cleanHtml;
}
```

---

## 2. Forbidden Practices

| Forbidden Practice | Vulnerability Risk | Required Alternative |
|--------------------|--------------------|----------------------|
| Direct `element.innerHTML = rawString` | Stored / Reflected XSS | Use `renderMarkdownSafely()` or `textContent` |
| `eval()` or `new Function()` | Arbitrary code execution | Standard JSON parser / native loops |
| Hardcoding external links with `target="_blank"` without `rel="noopener noreferrer"` | Tabnabbing vulnerability | Always attach `rel="noopener noreferrer"` |
| Exposing plain auth tokens in URL query params | Token leakage in browser history/logs | Use HttpOnly cookies or Authorization header |
